# Jw_cadとの差とGit連携の候補

調査日: 2026-10-02。対象はこのリポジトリのschema 0.3、比較対象はJw_cad 10.03.6。バージョンは[公式ダウンロード](https://www.jwcad.net/download.htm)、機能の存在は[公式変更履歴](https://www.jwcad.net/versioninfo.htm)で確認した。本CADの判定はソースとテスト・受入文書に基づく。今回、Jw_cadやDesktopを操作した比較試験は行っていない。

日常の建築作図を速くする機能と、図面交換の範囲が主な不足である。線・寸法・ブロックなどの基本機能は既にあるため、その再実装より、実際の作業で手順が増える箇所を優先したい。Git連携は既存の意味差分を土台に、任意版比較、変更単位の保存、競合解決へ広げる価値がある。

## 既にある機能

| 分野 | 実装済みの範囲 | 残る制約・主な根拠 |
|---|---|---|
| 作図・修正 | 線、連続線、円、円弧、文字、点、矩形、移動、複写、削除、回転、反転、複線、切断・延長、端点編集、ストレッチ、面取、角丸、矩形配列 | [コマンド一覧](../apps/viewer/src/command-registry.ts)、[編集操作](../crates/cad-edit/src/lib.rs)。全形状に全操作が使えるとは限らない |
| スナップ・入力 | 端点、中点、交点、中心、四半点、最近点、垂線、絶対・相対・極座標、直交入力 | `SnapKind` とコマンド入力。接線スナップは列挙にない |
| 寸法 | 平行、水平、垂直、連続、基準、角度、半径、直径、同一スコープの図形参照 | [寸法モデル](../crates/cad-model/src/dimensions.rs)。寸法から形状を駆動する機能、配置ブロック内部への参照はない |
| ブロック・ハッチ | 作成、配置、定義編集・複製、反転、一様倍率、solid/parallel/cross、閉領域拾い | ハッチは曲線をポリゴン化し、境界に自動追従しない。ブロック定義変更は全配置へ影響 |
| レイヤー・用紙 | グループ、表示、ロック、分離、印刷対象、図面追加・複製、用紙、縮尺、原点、余白、プロット範囲 | [Desktop](../apps/viewer/src/main.tsx)、[モデル](../crates/cad-model/src/lib.rs) |
| 表示・出力 | ズーム、前画面、両ボタンの表示操作、印刷プレビュー、SVG/PDF、JWW import/export | 両ボタンの表示操作をクロックメニュー全体の実装とは扱わない |
| 履歴・レビュー | Undo/Redo、外部変更監視、図形コメント、AIコンテキスト、HEAD対作業中の意味差分 | アプリ履歴とGit履歴は別。直接ファイル編集はUndoに入らない |

楕円は正本・入出力・ブロック内作図にある。一方、通常図面のコマンド一覧には楕円作図がない。「楕円未対応」ではなく、通常図面からの作図操作が不足している。

## Jw_cadに対する不足候補

優先度はP1=日常作業・移行で先に扱う、P2=利用頻度を確認して扱う、P3=専門用途が決まってから扱う。工数は相対見積りで、S=既存モデルを使う局所変更、M=複数層の変更、L=新形式・新モデル・互換性検証を伴う変更。

以下のJw_cad側の機能名は[公式変更履歴](https://www.jwcad.net/versioninfo.htm)に記載がある。すべてが同じ操作感・出力精度であるという判定ではない。

| 優先 | 候補 | 本CADで確認した不足 | 最初の実装と受入条件 | 工数 |
|---|---|---|---|---|
| P1 | 建築作図支援 | 建具平面・断面・立面、線記号変形、2線・中心線の専用コマンドがない。ブロックはあるが寸法指定で生成する建築部品機能はない | 開き戸・引戸・窓と壁の2線作図を既存プリミティブで生成。幅・壁厚・左右・基点をプレビューし、寸法変更後も向きと配置が一致 | M |
| P1 | 図面間の部品再利用 | Copyは同一図面内。図面間クリップボード、JWK/JWS部品読込、部品パレットの共通管理がない | 正本部品のコピー・貼付を先行。ID、寸法参照、レイヤー、ペン、ブロック名衝突を再割当し、別プロジェクトでもCAD checkを通す | M |
| P1 | 文字編集 | 検索・一括置換/style変更・計算注記に加え、上向き一字ずつの縦列注記をCLI/Desktop/SVG/PDFへ実装。既存文字とIDを保持しpreview/CAS/Undo | [縦列の座標と交換範囲](annotation-writing.md)。JWW/DXFは報告付き一文字展開。字体の縦組み・縦中横・外部エディタ・式依存再計算・native JWW縦字の再現は残る | M |
| P1 | 混在縮尺・印刷 | SVG/PDFの独立した縮尺・原点・クリップ付きビューポート、CLI/Desktopのレビュー適用とUndo、Git元図面依存署名を追加。JWW group縮尺は保持するが混在取り込みは従来の警告付き1/1 | 1000mmを1:100で10mm・1:20で50mm出図することを検証。JWWのクリップ/配置変換、紙上差分オーバーレイと交換先確認は残る。[設定・制約](sheet-viewports.md) | L |
| P1 | JWWの版・文字互換 | 入出力の編集可能範囲はv600、生成文字列はCP932。未知クラス・非対応版は保存専用 | 現行Jw_cadのUnicode対応と差がある。日本語・CP932外文字・各レコードのfixtureを増やし、非対応を検出。新形式対応は仕様と実データを確保してから | L |
| P1/P2 | DXF、SXF、JWC交換 | CLIの入出力はJWW、SVG、PDFのみ。直接交換できない | 利用先を確認してDXFを優先。線・円弧・文字・ブロック・単位・線種の小さな範囲から報告書付きで対応。SXF/JWCは別工程 | L |
| P2 | 下絵画像 | Entityに画像型がない。Jw_cadは画像挿入・同梱に対応 | 写真・スキャン画像の配置、透過、基準2点で縮尺合わせ。リンク切れ検出とPDF出力、Gitでの画像保持方法を同時に決める | M–L |
| P2 | 測定・集計 | 寸法評価・領域判定はあるが、測定・面積集計・表計算コマンドがない | 距離、周長、面積を選択図形から取得し、mm/m・mm²/m²を明示。曲線・穴・自己交差の扱いを検証してCSVへ出す | M |
| P2 | 作図の短縮操作 | 接線・接円、中心線、分割、一般図形の倍率変更、属性取得、クロックメニュー設定の専用操作がない | 使用頻度の高い順に追加。既存のSnapKind、preview、Batch、Undoを使い、線を拾って次の作図へ属性を引き継げるようにする | M |
| P2 | 曲線・楕円の操作 | 楕円データはあるが通常図面の作図入口が不足。自由曲線のモデルがない | 楕円入口を先行。自由曲線はポリライン近似か新型かを選び、許容誤差とJWW出力レポートを定義 | S / L |
| P2 | 複数図面の出力 | PDFは一回一図面、render SVGは先頭図面。連続印刷・一括PDFと出図セットがない | `render --drawing`、複数図面PDF、出図順・図番・レイアウト指定。同じ正本スナップショットから全ページ生成 | S–M |
| P2 | 外部変形・設定移行 | Jw_cad外部変形やJWF設定を読み込む互換APIはない | 既存バッチの移植が必要か確認。まず正本に対する選択集合→プレビュー→検査→適用のCLI/APIを用意。Windowsバッチの実行互換は別途判断 | M–L |
| P3 | 2.5D、日影図、天空図 | 角柱の平行投影・指定太陽角の地面影・水平天空図を追加。地形・傾斜屋根・隠線・太陽位置/時間日影・法規比較は残る | [計算条件・根拠と検証範囲](massing-calculations.md)を保持。法規合格を主張しない | L |

Jw_cadの「パラメトリック変形」を一般的な拘束ソルバーと同一視しない。本CADにもstretchと参照寸法があるため、「パラメトリック機能がすべてない」とは言えない。寸法駆動・拘束ソルバーは本CADの追加候補だが、今回Jw_cadとの差を埋める最優先項目には置かない。

## Git連携で追加する価値があるもの

既存の[HEADスナップショット](../apps/viewer/src-tauri/src/head_snapshot.rs)はHEADのOIDとソースmanifestでキャッシュする。[意味差分](../crates/cad-diff/src/lib.rs)は図形IDで変更理由を分類し、用紙・レイヤー・スタイル等の設定変更も返す。これを次へ拡張する。

| 優先 | 候補 | 利点と実装上の要点 | 受入条件 |
|---|---|---|---|
| P1 | 任意版・indexの比較 | commit/tag/branch、HEAD↔index、index↔作業中を選ぶ。Git refを受けるCLIと比較元表示を追加。外部commitだけの変更でも表示更新できるようGit側の状態を監視 | ソースを変えないcommit/index変更でも比較が更新。Git外や欠けた正本は比較不可と明示 |
| P1 | 依存関係による表示変更の差分 | 参照先変更による寸法値、共有ブロック変更による全配置の表示を比較。現在の図形フィールド比較に加え、評価結果と逆参照を使う | 壁を300mm動かすと、壁だけでなく5300mmへ変化した参照寸法も影響一覧と差分図に表示 |
| P1 | 出図と版の対応 | PDF/JWWとレポートにcommit OID、正本manifest、図面・layout、CLI版を対応付ける。作業中がdirtyならOIDだけで特定したと扱わない | 再生成で対象版を確認でき、未commitの図面や古いレポートの混入を検出 |
| P1 | 図形単位のstage/commit | 「壁移動だけ」「注記だけ」を保存。選んだ図形に必要な寸法・レイヤー・スタイル・ブロック定義を追従させる | 実際のGit index全体を検査し、壊れた参照をcommitしない。未選択の正本と他の既存stageを保持 |
| P1 | entity単位の3-way merge | base/ours/theirsをIDとフィールドで比較し、別図形の編集は合成。同じ図形でも座標・注記・スタイルの衝突を表示 | delete対変更、寸法参照、設定・ブロック変更を検出。候補の全プロジェクトを検査し、承認前に作業中データを置換しない |
| P2 | 変更履歴と図形blame | 選択図形をいつ・なぜ変えたか、図面上の位置から過去版へ辿る。再取り込みによるID変更は履歴連続性がないと示す | 行番号変更で別図形を誤って追わず、前版の図形を表示できる |
| P2 | PR用レビュー資料 | 意味差分JSON、両版のPDF/SVG、注記、警告をCIのartifactとして生成。ソフトウェアCIとは別にCAD正本を検査 | 複数図面と共有ブロック変更を漏らさず、実機未確認・近似警告をレビューに残す |
| P2 | コメントの版紐付け | 現行コメントはentityに紐付くが、その版の形状との対応を持たせたい | ID、対象版、元座標をアプリ経由で記録。図形削除・変更で古いコメントと分かる。AIによるcomments直接編集は不要 |
| P2 | Git運用の入口 | 初回保存、履歴比較、branch/worktreeで別案、手動syncの状態をUIに出す | Gitなしでも作図可能。branch切替で未保存・復旧候補を失わない。自動pushは初期値にしない |

`.gitignore`は既にbuild、exports、snapshots等を除外している。一律formatによる全行変更は避け、更新したNDJSON行とIDを維持する。来歴付きJWWを再現するには正本だけでなく `interop/jww/` も必要なので、生成物と同じ理由で除外しない。

最初は任意版比較と出図manifestから着手する。stage/mergeはプロジェクト全体の依存関係を扱うため、その後に進める。単純なテキストmerge driverを先に自動適用すると、構文が正しくても参照寸法や定義が壊れる。

調査時の受入図面では、右壁を300mm動かして寸法表示が5300mmになっても、意味差分は壁polyline一件だけだった。2026-10-03の実装で、評価済み寸法と共有ブロックの内容を比較する依存差分を追加した。回帰テストは寸法の5000→5300mmと全ブロック配置への影響を確認する。

## 推奨する着手順

1. 既存受入図面のJw_cad表示・印刷確認とfixtureの追加。文字・線種・ブロック・ソリッド・混在縮尺の実差を記録する。[受入チェックリスト](cad-acceptance.md)は現在実機未実施。
2. 任意版比較、選択図面のSVG、出図manifest。既存のchecker・diff・rendererを使い、変更を評価できる環境を先に広げる。
3. 図面間コピー、文字検索・置換、建具と2線作図。実際の平面図と展開図で操作回数・再利用のしやすさを評価する。
4. Git stage/mergeとDXF。競合fixtureと交換先アプリの実データを用意する。
5. 下絵・集計・専門機能は利用者の作業頻度に合わせて追加する。

## 図面編集スキル

- [`cad-drafting`](../.agents/skills/cad-drafting/SKILL.md): 既存スキルを更新。正本の座標・用紙・複写時のIDと寸法参照、ブロック・ハッチ、編集競合、保存専用JWWの扱いを追加。平面図から壁面展開図を作る手順も保持した。
- [`cad-review`](../.agents/skills/cad-review/SKILL.md): 新規作成。比較元を明示し、意味差分・設定・寸法・印刷・互換性を確認する。図面レビュー用で、アプリ本体のコードレビューとは別。

呼び出し例:

```text
$cad-drafting を使い、平面図の指定した壁を300mm移動し、参照寸法とハッチを確認してPDFを出力して。
$cad-review を使い、このCADプロジェクトのHEADと作業中の図面を比較し、出図への影響を報告して。
```

調査後に全候補の実装が依頼された。進捗と残りは [実装記録](../plans/011-jwcad-parity.md) に記載する。Git比較・出図セット・merge候補、建築作図・計測・編集要求CLIを追加し、スキルも現在のコマンドへ更新している。全候補が実装済みという意味ではない。

## 今回の検証

両スキルはskill-creatorのvalidatorに合格し、ローカル参照リンクと `git diff --check` も確認した。既存受入図面のコピーで右壁を300mm移動し、両版のCAD checkがエラー・警告とも0、意味差分JSON/SVG、完成図SVG、指定図面・レイアウトのPDF生成を確認した。SVGでは水平5300mm・垂直4000mmの表示を確認し、A3横PDFを画像化して寸法と用紙内の配置を目視した。

JWW専用checkはエラー0・警告12件、best-effort出力は105レコード・警告11件・blocker 0。すべての警告を確認し、用紙向き、色・線種の近似、寸法とハッチの展開が含まれることを確認した。JSONレポートは検証用出力とともに `build/cad-skills-4kn99n12/` に保持している。Jw_cad実機の確認とアプリ全体の回帰試験は今回行っていない。
